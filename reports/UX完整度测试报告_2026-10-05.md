## 二、关键发现（P0 级 — 必须修复）

### 1. Angular `<base href="./">` 部署缺陷
dist/imatuproject/index.html 的 `<base href="./">` 在静态服务器（非 file:// 与非 ng serve）部署时会导致**任何深层路由直接 URL 访问失败**：
- 直接访问 `http://localhost:8080/auth/login` 时，浏览器从 `/auth/` 加载 index.html
- `<base href="./">` 解析为 `http://localhost:8080/auth/`
- 脚本请求 `http://localhost:8080/auth/runtime.xxx.js` 被 SPA fallback 返回 HTML
- 浏览器拒绝加载：`Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of "text/html"`
- **修复**：dist 时改用 `<base href="/">`，或在构建配置中指定 `baseHref: '/'`
- **影响**：14+ 多层路由直接 URL 访问失败，必须由首页 pushState 进入

### 2. 后端 CORS 阻断（外部浏览器访问场景）
- `main_ai_edu.py` 的 CORS 白名单只允许 `http://localhost:4200` 与 `http://localhost:3000`
- 当前使用 `http://localhost:8080` 测试，未在白名单 → 所有 API 被拒
- **影响**：登录失败、用户数据加载失败、首页显示"后端未启动"
- **修复**：扩大白名单或读环境变量（生产只允许 4200；测试允许 8080）

### 3. 路由 404：/opensciedu/catalog、/opensciedu/knowledge-graph
- `app-routing.module.ts` 中 `path: 'opensciedu'` 只用 `loadComponent` 加载 `opensciedu-page.component`，**未注册 catalog 与 knowledge-graph 子路由**
- 直接 URL / 客户端跳转都返回 404 → ComingSoon 兜底
- **修复**：在 OpenSciEDU 模块下补 `path: 'catalog'` / `path: 'knowledge-graph'` 子路由，或在页面组件内做 routerLink

### 4. /vircadia 路由异常
- 重定向至 `/` 后脚本未加载（同时被 base href 问题牵连），页面空白
- `app-routing.module.ts` 中 vircadia 有 lazy module 路由，但 ModuleActiveGuard 要求 `ar_vr` 模块激活
- **修复**：检查 ModuleActiveGuard 在 ar_vr 未激活时的处理，并修复 base href
