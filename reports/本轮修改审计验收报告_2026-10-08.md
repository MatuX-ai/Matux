### 2.2 修正原报告遗漏的 3 项修改

审计发现除原报告 8 项外，本轮还新增了 3 项修复：

#### A. auth.service.ts 增加 signIn/signUp/phoneLogin HTTP 超时保护

```typescript
// 新增 rxjs 操作符
import { catchError, map, tap, timeout } from 'rxjs/operators';

// 新增超时配置（带 8s 下限保护）
private readonly SIGNIN_HTTP_TIMEOUT_MS: number = (() => {
  const configured = (environment as { httpTimeout?: number }).httpTimeout;
  return Math.max(configured ?? 8000, 8000);  // 登录路径至少 8s
})();

// signIn / signUp / phoneLogin / phoneRegister 均加 timeout()
signIn(credentials: LoginRequest): Observable<AuthResponse> {
  return this.http.post<AuthResponse>(`${this.API_BASE_URL}/signin`, credentials).pipe(
    timeout(this.SIGNIN_HTTP_TIMEOUT_MS),  // ✅ P1 修复：登录 8s 超时
    ...
  );
}
```

**修复逻辑**: 桌面端冷启动后端可能需要 10~30s，超时 8s 会快速给错误反馈。
**等级**: P1（重要）

#### B. login.component.ts Fast Mode 启动优化（P3）

```typescript
// 新增字段
fastMode = false;           // 是否 Fast Mode
backendReady = true;        // 后端是否就绪
fastModeHint = '';          // Fast Mode 友好提示文案
fastModeRecoveryHint = false; // Fast Mode 登录失败时显示恢复引导

// 订阅 startupMode（启动模式）
this.startupMode.mode$.subscribe((mode) => {
  this.fastMode = mode.fastMode;
  this.fastModeHint = mode.fastMode
    ? '⏳ 学习优先模式：后端正在后台启动（10~30s），登录将在后端就绪后自动可用'
    : '';
});

// 订阅 moduleStatus（后端/模块就绪）
this.moduleStatus.healthy$.subscribe((healthy) => {
  this.backendReady = healthy;
  this.cdr.markForCheck();
});

// Fast Mode 登录失败时显示"取消学习优先模式 + 退出"按钮
quitAndRetryInNormalMode(): void {
  localStorage.setItem('matux-fast-mode-enabled', '0');
  this.pushLine('已取消学习优先模式偏好，正在重启应用', 'info');
  window.electronAPI.quit();  // IPC 通知主进程退出
}
```

**修复逻辑**: Fast Mode 启动后端可能未就绪，13s 超时后用户可能误判为密码错误。新增友好引导让用户取消偏好并重启。
**等级**: P3（体验打磨）

#### C. login.component.ts 登录阶段时序调整（P1）

```typescript
// 原时序：validating 250ms → contacting 350ms → verifying 350ms → loading 250ms → 30s 超时兜底
// 新时序：validating 80ms → contacting 立即 → 13s 超时兜底 → 成功后 verifying/loading 各 180ms

private readonly LOGIN_FALLBACK_TIMEOUT_MS = 13000;  // ✅ 30s → 13s

runPhase(LOGIN_PHASES['validating']);
await this.delay(this.prefersReducedMotion ? 40 : 80);   // 250ms → 80ms
runPhase(LOGIN_PHASES['contacting']);

await Promise.race([
  doLogin(),
  this.delay(this.LOGIN_FALLBACK_TIMEOUT_MS).then(() => {
    throw new Error('后端服务响应超时，请检查后端是否启动完成');
  }),
]);

// 成功后：verifying → loading → ready（不再预占 1.2s 动画）
runPhase(LOGIN_PHASES['verifying']);
await this.delay(this.prefersReducedMotion ? 60 : 180);
runPhase(LOGIN_PHASES['loading']);
await this.delay(this.prefersReducedMotion ? 60 : 180);
runPhase(LOGIN_PHASES['ready']);
```

**修复逻辑**: 旧实现对齐 30s 后才报错，且阶段动画预跑 1.2s 让用户以为卡死。新实现 13s 内反馈，且验证和加载动画仅在登录成功后展示。
**等级**: P1（重要）
