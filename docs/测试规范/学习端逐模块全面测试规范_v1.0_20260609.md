## 一、测试方法论

### 1.1 核心理念

每个模块执行 **5 步测试闭环**：

| 步骤 | 名称 | 内容 | 通过标准 |
|------|------|------|----------|
| S1 | 编译验证 | `ng build` 无 TS 错误 | 0 error, 0 warning |
| S2 | 路由可达 | 导航到模块 URL，页面加载 | 页面渲染无白屏、无 console error |
| S3 | 功能完整性 | 逐功能点验证（CRUD、API 交互、状态变更） | 所有功能点与 PRD 一致 |
| S4 | 边界与异常 | 空数据、网络断开、非法输入、并发操作 | 优雅降级，无未捕获异常 |
| S5 | UI 响应式 | 1024x768 / 1920x1080 / 缩放 125% | 布局不错乱、文字不溢出 |

**每步发现问题 → 定位 → 修复 → 回归验证 → 继续下一步**

### 1.2 问题分级标准

| 级别 | 定义 | 处理策略 |
|------|------|----------|
| P0 (阻塞) | 编译错误、白屏、功能完全不可用 | 立即修复，阻塞后续测试 |
| P1 (严重) | 功能部分不可用、数据错误、安全问题 | 当前模块内修复，回归验证 |
| P2 (一般) | UI 错位、交互不流畅、边缘情况 | 当前模块内修复，回归验证 |
| P3 (轻微) | 样式微调、文案优化、建议改进 | 记录后继续，模块末尾统一修复 |

### 1.3 执行策略

1. **严格顺序**: M1 → M2 → M3 → ... 按编号顺序，不跳模块
2. **闭环原则**: 每个模块 5 步全部 PASS 后才标记完成，进入下一模块
3. **回归守卫**: 修复问题后，重新执行该模块 S1-S5 全部步骤
4. **进度追踪**: 使用 TodoWrite 实时记录每模块 5 步的通过状态
